# 中英文界面验证

2026-10-05，Windows 11 Enterprise build 26200、x64，i7-11700K / 32 GiB。仅内置简体中文与英文，默认简体中文；通过托盘右键的“简体中文”与“English”单选项即时切换。

## 行为与实现

选择保存到数据目录 `language.txt`，值为 `zh-CN` 或 `en`。缺失、损坏、未知或过长内容回退到简体中文；与主题、图标、英文输入等设置独立。安装器的语言选择独立，不覆盖应用选择。

菜单、搜索提示、无结果提示、目录/应用数量与刷新状态、产品自己的错误和 `--help` 均有两种文本。应用名称、中文/拼音/首字母搜索及输入内容保持原样；界面语言不控制键盘布局或 IME 模式。Windows 原生系统错误的正文仍按系统语言返回。

`i18n` 使用静态双语文本表，不新增 Rust 依赖、翻译文件解析器或线程。状态保存结构化数量与错误值，切换时可重新翻译已有通知；当前语言的 UTF-16 文本在状态/语言变化时缓存，不在搜索时翻译候选或读盘。切换不重建索引、字体或窗口，不改变结果选择和文本选择。

测试发现此前的 EM_SETCUEBANNER 没有实际生效。该 API 要求 Comctl32 v6 的清单配置，见 [微软说明](https://learn.microsoft.com/en-us/windows/win32/controls/em-setcuebanner)。现在空输入框直接用现有 GDI 绘制灰色提示，不引入该控件依赖，也不建立额外位图；实际文本、选择、光标与 IME 仍由原生 Edit 处理。仅在非组字且实际文本为空时绘制，开始组字时走原生路径。

## 验证

Rust 1.95.0 / MSVC，release opt-level 3、fat LTO、1 codegen unit、panic abort、strip、静态 CRT。`cargo test --offline` 通过 32 项单元测试与 5 项搜索流程测试；`cargo fmt --check`、`cargo clippy --offline --all-targets -- -D warnings` 和 `cargo build --release --offline` 通过。

单元测试检查独立保存、反复替换、设置损坏回退、已有通知及嵌套错误随语言更新；真实 GDI 字体度量确认中英文页脚在 96/120/168/192 DPI 下均能放入现有宽度。

`native_probe.exe --language` 通过 **202 项检查**，使用 10 个合成 exe 入口和隔离数据，不执行这些文件、不打开用户应用。覆盖实际托盘全部菜单文本与单选标记、两个方向的菜单切换、20 次即时切换、语言重启保存、查询/文本选择/结果/选中行/窗口几何/键盘布局保留、索引及其他设置文件不变、既有状态与失效入口错误重新翻译、实际中英帮助及参数错误弹窗、语言保存失败提示。缺失入口在 Shell 执行前报告，没有启动进程。

已检查亮色中英输入提示、亮/暗英文无结果和实际菜单截图。最终双语原始证据在忽略目录 `runtime/probe-language/1791139154066/`；早期失败证据保留。探针现在等待弹窗内容和可见状态、排队关闭并限定退出等待；菜单被前台切换提前关闭时按有限次数重试。早期挂起的测试进程已按准确路径/参数清理，用户实例通过正常关闭/恢复脚本保护。
