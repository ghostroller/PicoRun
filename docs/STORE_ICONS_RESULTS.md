# Store 应用图标修复

2026-10-09：最近的 `ea76fc9` 接通了 AppsFolder 发现与 AUMID 启动，但 `request_icons` 把所有打包目标变成空路径，worker 对空路径返回 None，因此结果行没有图标。旧文档的通用图标说明与实际实现不符。修复后，本机 22 个打包入口在三轮实际窗口测试中均取得图标；ChatGPT 和 Microsoft Store 的亮暗主题图案已逐张核对。

## 实现

- 图标请求、元数据和资源键保留 `LaunchTarget` 类型；文件路径与 AUMID 不混用。普通 `.lnk` 继续读取原图标位置/目标资源并直接提取，不修改应用打开方式。
- 在已有 STA 图标 worker 中解析 `shell:AppsFolder\AUMID` 的绝对 PIDL，以 `SHGetFileInfoW(SHGFI_PIDL | SHGFI_ICON | SHGFI_LARGEICON)` 取得 owned HICON。PIDL 在单次调用内释放，HICON 由既有 Arc 所有权释放；没有跨线程的 COM 对象、UI 借用或请求锁跨原生调用。
- Store 和普通入口共用 48 条资源图标缓存、512 条/128 KiB 元数据预算；预算包含 AUMID 字符串容量及容器槽。当前 UI 快照、一个共享通用图标、原有两块共 128 KiB 解析缓冲和系统 Shell 内部缓存另计，不将资源缓存上限冒充完整进程占用。
- 同一身份重用资源/负缓存，F5 清除后重取；原生提取失败可回退共享通用图标。拒绝非 AUMID、NUL、Shell 路径分隔符和超长 UTF-16 身份后才进入 Shell。只请求可见结果；图标默认关闭，关闭时回收 worker、快照与缓存，无新依赖、线程类型或轮询。

ABI 核对本机 Windows SDK 10.0.26100.0 `shellapi.h`；SHFILEINFOW 包含完整 260/80 字符输出缓冲，x64 大小为 696 字节，x86 声明遵循 SDK 的 pack(1)，但未构建或运行 32 位版本。原生调用、后台线程建议和所有权参考微软 [SHParseDisplayName](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shparsedisplayname)、[SHGetFileInfoW](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shgetfileinfow)。

## 正确性与实际窗口

`cargo fmt --check`、`cargo test --offline`（57 单元 + 5 集成）、`cargo clippy --offline --all-targets -- -D warnings`、`cargo build --release --offline`、`git diff --check` 均通过。新增测试覆盖 Shell ABI、非法身份、AUMID 与文件资源分隔、负结果共享与 F5 清除；现有搜索、中文/全拼/首字母、缓存和快捷方式测试继续通过。

新增 `native_probe.exe --packaged-icons [--reference]`，使用忽略目录内的独立数据和 Ctrl+Alt+Shift+F9。原版、修复版各三个独立主进程，每轮都发现 330 项，其中 22 项打包入口。探针在原生 Edit 查询、定位对应结果（含同名时的方向键选择），以测量模式下的标量 AUMID 哈希核对所选目标，等待异步完成后检查图标非空、提取计数、无新增通用回退。三轮全部 66 次打包入口检查通过；两项报告应用的四张亮暗截图已目视确认实际图案。重复查询缓存命中，F5 重取、图标关闭不创建 worker、关闭后的后续查询、正常退出码 0 均通过。没有打开安装的 Store 应用。

普通路径回归使用既有 `prepare_icon_fixture.ps1` 和 `measure_icon_switch.ps1` 的忽略目录副本：只保留本版 off/on 两个模式，使用可用的备用热键。500 个合成快捷方式含一个显式 Shell32 图标覆盖；每模式 60 个逐项查询、1000 次快速请求、缓存界限、F5、关闭重查询和正常退出通过，覆盖图标截图已核对，没有打开用户应用。该工具的其余计时不用于下表。

旧完整 `native_probe.exe --icons` 在本机托盘弹出菜单阶段失败（tray popup menu did not open），不能报告整套原生菜单/IME 回归通过。上述独立回归使用相同菜单命令处理器验证图标开关，但不替代真实弹出菜单选择或完整 IME 会话。早期普通脚本的 Ctrl+Alt+F12 未完成窗口初始化，换用 F9 后通过；失败输出保留。首轮 Store 探针截图被 DPI 虚拟化裁剪，已补 `enable_dpi` 并重新完成六个主进程；以下仅使用最终正确缩放的批次，首轮另存。

## 完整进程成本

实际机器是 Intel Core i9-11900K、约 16 GiB、Windows 10 Pro 22H2 / 10.0.19045、x64；不是历史报告的 Windows 11 机器。Rust/Cargo 1.95.0、MSVC x64，release 为 opt-level=3、fat LTO、codegen-units=1、panic=abort、strip=true。修复未发布、包版本仍为 0.1.2 工作副本。

先原版、后修复，各三个新进程，深色、英文输入打开。每组第一轮删除磁盘索引缓存，后两轮保留缓存，仍会启动扫描；未清除操作系统文件缓存、Shell 缓存或工作集，不能称物理冷启动。先关闭图标取得隐藏/显示基线，再在单项 ChatGPT 结果上开启图标、遍历打包应用、100 次预热/100 次测量（五个固定查询循环）、一次 F5、两秒隐藏空闲、最后关闭图标。初始隐藏采样在发现原生 Edit 后立即执行，初始化可能尚在完成；启动时间也是到窗口创建，不是完整交互就绪时间。

## 真实窗口响应

窗口计时范围为跨进程 WM_SETTEXT → 查询同步 → WM_PAINT；异步图标等待在每次查询计时外另行完成。不是实际键盘调度、IME 或显示扫描输出延迟。P50/P95 为每轮 100 样本的分位数；下表的查询栏为各轮分位数的中位数，不是合并 300 个样本。

| 指标，ms | 原版 | 修复 |
| --- | ---: | ---: |
| 首次无索引缓存启动 | 434.1934 | 346.1711 |
| 后两次有缓存启动 | 345.0690 / 342.4686 | 361.7579 / 334.6087 |
| 三次启动 P50 / P95 | 345.0690 / 434.1934 | 346.1711 / 361.7579 |

首项就绪包含开关处理、worker 初始化、Shell 提取、完成消息及同步绘制。原版首项非空图标数为 0、修复为 1，不能将两列等待时间理解为等价提取速度。可见本轮查询 P50 有增量，P95 中位数接近不构成无回归保证。
