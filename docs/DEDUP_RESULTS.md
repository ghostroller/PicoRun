# 2026-10-04 保守应用去重与性能对照

最终实机对照：原始 396 项 → 346 项，合并 50 个重复入口（12.63%），目录读取失败为 0。截图中的 AB Download Manager 与 AdsPower Browser 各保留一项。早期试验的来源为 394 项，数量随后发生变化；本报告使用最终批次自身的前后对照，不混合两批数据。

## 行为与实现

仍扫描用户 Programs、公共 Programs、用户桌面、公共桌面，最多递归 16 层，跳过重解析点。显示名取入口文件名。相同入口路径在 COM 解析前跳过；同名（去首尾空白、转小写）且启动信息相同的普通本地 Unicode `.lnk` 才合并。

启动键分字段比较目标路径、完整原始 UTF-16 参数、工作目录、Show、权限等标志、快捷键和支持的完整扩展块。参数的大小写、引号和空格全部保留；路径仅做大小写/斜杠归一化，空工作目录保持为空。不调用 Resolve、canonicalize、环境展开，也不读取目标 exe。不同名称、参数、工作目录、权限、窗口状态或扩展元数据保留独立入口；裸 exe 不与快捷方式合并。

支持 Tracker、PropertyStore、IconEnvironment 和 KnownFolder 扩展块，保留其完整字节，包括 KnownFolder GUID 和 IDList 偏移；差异或顺序不同也不合并。控制台设置、Darwin/MSI、兼容层、其他未知块/标志、ANSI、网络/相对目标、相对/环境变量工作目录等不形成启动键。先沿用原规则确认目标为 `.exe`；通过这一检查、但无法安全构造完整去重键时，保守保留原入口。已损坏到无法识别应用的链接仍沿用原来的不索引规则。

代表项优先用户 Programs、公共 Programs、用户桌面、公共桌面；显式 `--source` 按传入顺序优先，同来源选字典序较小的路径。结果按预计算名称键和原始路径稳定排序。F5 重新扫描全部来源，可在首选入口删除后晋升备用来源；目录失败恢复的旧入口当前元数据未知，保守只按入口路径去重。

只在同名碰撞时读取附加信息，对完整链接设置 256 KiB 上限，复用缓冲并最多额外读一字节检查文件增长，缓冲 capacity 另计。临时目标池共享相同字符串，最多 512 条/128 KiB 字符串及 Rc 头；超出后碰撞时重读 COM。启动键结构和所属容量预算为 2 MiB，HashMap 桶、分配器及候选路径开销另计；超预算的新键独立保留。扫描后释放目标池、去重键、路径查重集合与 reader，再生成幸存项的拼音键。模型和 `apps-v1.bin` 格式没有增加常驻元数据，打开仍由 Shell 执行选中的原 `.lnk`。

依据微软格式独立实现，未复制 GPL 启动器代码。技术来源与其他启动器的固定提交研究见 [RESEARCH.md](RESEARCH.md)。

## 完整进程与窗口口径

合成 500/2,000/10,000 个实际 `.lnk`，分别 0%/50% 重复，保留中文混合名称；每种配置每个版本 5 个新进程，合计 60 个。固定受控 target 和参数，重复项复制到另一子目录；50% 场景 after 项数为输入的一半。交替 before/after 顺序，逐进程清除自己的索引缓存；是真正的新进程/冷目录索引，OS 文件缓存已暖，不是重启机器或清空系统缓存后的冷盘启动。另对真实来源各 5 个新进程，合计 10 个；两组过程和统计独立。

均图标关闭、英文选项默认关闭、隔离设置目录；启用既有测量消息和保持测量窗口选项。启动计时包括进程创建、扫描、索引/缓存、窗口/托盘/热键初始化及消息循环就绪，窗口等待轮询为 5 ms。F5 是同步消息完成扫描、替换索引、保存缓存的墙钟时间。不是仅比较哈希查重函数。

每进程固定 4 个查询，先预热 20 次，再计时 100 次；消息路径包含原生 Edit 的 WM_SETTEXT、查询同步、WM_PAINT。这里不是实际物理按键、IME 组合输入或桌面合成器呈现延迟。表中的窗口 P50/P95 为各进程 100 次分位数，再取 5 进程中位数；启动/F5 为 5 个过程值的 nearest-rank P50/P95，P95 实际等于最大值，不能代表稳定的长尾。真实来源由 PowerShell/C# 驱动，合成由 Rust 驱动，主机计时开销不同，只在各自表内做前后比较。

内存用 GetProcessMemoryInfo，阶段依次为隐藏初始化、显示/查询后、F5 后、隐藏空闲前/后。表使用隐藏空闲 0.5 s 后的完整进程 PrivateUsage/WorkingSetSize，各 5 进程的 P50/P95；峰值为该进程创建至测量结束累计 PeakPagefileUsage/PeakWorkingSetSize 的组内最大值。前者是系统 API 的峰值提交口径，不是逐次采样最大 PrivateUsage。包括 Shell、CRT、字体、原生输入组件和分配器保留页；没有清空工作集。

## 重现与边界

冻结 before exe 与 native_probe 位于忽略的 `runtime/dedup/baseline/`，最终 `times.csv`、`memory.csv`、查询/回归日志与阶段内存均在 `runtime/dedup/`；实机前后数据在其 `real/` 子目录。真实入口路径只在该忽略目录的私有缓存中，没有提交个人清单。早期迭代结果另行保留，不用于最终表格。

先正常退出已运行的 PicoRun，保留 before 文件并构建 release，再运行：

```powershell
Start-Process target/release/native_probe.exe -ArgumentList '--dedup','--bench' -WindowStyle Hidden -Wait -PassThru
tools/measure_dedup_real.ps1
python tools/summarize_dedup.py runtime/dedup
python tools/summarize_dedup.py runtime/dedup/real
target/release/search_bench.exe
```

`measure_dedup_real.ps1` 会拒绝覆盖已有实机报告，先移走自己创建的该批报告再重测。Python/PowerShell/C# 仅为开发评测工具，启动器没有这些运行时依赖。Windows 10、x86、极低内存/换页机器、其他系统和真实物理按键的端到端延迟未在本轮验证；图标开启和中文组合输入成本沿用各自专项证据。保守规则仍可能留下同名入口，原因可包括不同启动信息、不支持的元数据或预算回退，不按名称或 exe 路径单独强行合并。
