## 第一个闭环

1. 从用户/公共开始菜单、桌面等已知应用入口建立真实索引，优先 `.lnk`。使用系统已知目录，考虑重定向和访问失败；单个目录失败不应清空可用结果。明确报告 UWP/Store 应用是否支持，若暂缓则写进实际限制。
2. 实现单实例、全局热键、阻塞消息循环。默认 Alt+Space；冲突可配置，失败要可见。没有窗口时不设周期定时器。
3. 原生 Edit + 自绘结果列表；首版竖排。方向键选择、Enter 打开、Escape 隐藏，失去焦点隐藏；输入法组合期间 Enter 不执行应用。
4. 监听真实文本变化，复制不重算，删除/粘贴不漏更新。若投递消息合并刷新，执行前同步当前文本，防止旧候选启动。
5. Shell 打开保存的原始入口，准确处理路径、引号、参数和工作目录。不要把 `.lnk` 转成裸 exe 然后丢失其参数。对失败给出轻量可见反馈。
6. 原生 renderer 消费独立 Theme；搜索层不知道字体、颜色、行高。首版可先使用默认主题，配置格式再独立添加。

保持 Windows FFI 集中并写清安全条件。窗口回调必须处理重入与销毁，不得跨同步控件调用持有可变借用。字体、画笔、图标、COM 对象、热键和句柄按所有权释放；不在每次绘制重新生成结果/分页。

## 低内存与缓存

- 全拼和首字母在扫描/索引更新时生成，保留紧凑字符串，热路径不用大型词库。
- 保存带版本的紧凑应用缓存；启动可先读缓存，刷新形成新快照后替换。缓存损坏/入口失效要可恢复。缓存和使用记录存放用户目录，不写 exe 旁的只读位置。
- 不运行 PowerShell、Python 或其他外部脚本获取应用列表。旧调查中辅助 Python/PowerShell 会制造远高于原生核心的内存峰值。
- 首先不加载图标以建立真实内存基线；增加图标时只加载可见项并限制缓存。是否复用隐藏窗口，以呼出延迟和完整进程内存实测决定。
- 先保持全量线性扫描少量应用、固定前 12 项；几百项没有证据需要倒排索引、持续后台线程或增量筛选。
- 不调用清空工作集 API 来制作“低占用”结果；私有提交和工作集分别统计。

## 拼音与排序

已有全拼/首字母/简繁单字支持及明确词组覆盖。保留中英混合和未知字符，`ü` 用 `v`。优先为应用常见多音名称添加有依据的小型词组覆盖，并保留测试；不引入大体积 NLP 模型。

当前简单排名用于建立闭环，评分体验可能需要改进；不应直接复制旧工程 GPL 实现。之后通过中文名称、全拼、首字母、英文缩写、连续输入/删除、空输入、无命中、同名入口等固定样本验证排名。

## 验收与测量

- 用可控测试程序验证打开与路径/参数，不随意启动个人应用。检查热键冲突、单实例、正常退出和句柄释放。
- 用实际窗口检验 Delete、右键粘贴、Ctrl+V、Ctrl+C、IME 组合、快速输入后立即 Enter、DPI 缩放、焦点切换和结果选择。控制器单元测试不能替代这些 GUI 检验。
- 在当前机器测完整进程：隐藏、显示、输入、启动刷新、持续查询后的私有提交、工作集、峰值和空闲 CPU。
- 单独测 500/2000/10000 项纯搜索 P50/P95、索引构建成本和占用。能维持之前几百项数十微秒级核心作为探索目标，但必须用当前排名和拼音路径重测。
- 首轮探索目标：几百项隐藏状态私有提交尽量接近 2–4 MiB，显示状态尽量低于 8 MiB，预热纯搜索 P95 尽量低于 0.1 ms。**这些是待验证目标，不是已达到的指标或旧机器承诺**；如 Win32/标准库/图标导致超出，应解释拆分成本并实测优化。
- 当前 Windows 11 的通过结果不等于 Windows 10 实测。避免静态导入仅新系统支持的 API；兼容性、32 位支持和内存换页状态需要单独验证。
