# 应用来源补齐与验证

2026-10-09：依据固定版本的 [Flow Launcher 来源调查](FLOW_DISCOVERY_AUDIT.md)，独立补齐 App Paths、StartMenu 根目录、ClickOnce 入口与预计算名称别名。保持 Rust + Win32、空依赖列表、启动／F5 扫描和阻塞空闲。

## 实现与边界

- 默认扫描用户／公共 StartMenu 根目录及 Programs 子树，桌面来源保留；通过 Known Folder 定位并排除两类 Startup。仍限 16 层，不追踪 reparse point／符号链接；已知目录离线或解析失败时回补旧入口。
- 原生读取 HKCU／HKLM App Paths 的 32／64 位视图，严格处理 REG_SZ／REG_EXPAND_SZ、配对引号和现存绝对 EXE 路径，过滤失效、带参数、编码无效或不支持的值。相同名称、目标、Path 合并；不同名称、目标或环境独立保留，也不因 EXE 相同合并带参数的快捷方式。任一真实注册来源读取失败时整组回补旧快照，没有声明模拟 Shell 的 HKCU 优先级。
- 保存独立 AppPath 目标和可选 Path。无额外 Path 时 Shell 打开精确 EXE；有 Path 时仅在执行打开时启动一次性无窗自身 helper，把注册 Path 加到其私有 PATH 前面，再通过 Shell 打开精确 EXE。主进程环境不变；helper 无窗口、扫描、图标线程或单实例注册。标准句柄禁止继承，避免应用持有错误管道而使主程序等待应用整个生命周期。
- 接受 .appref-ms 和指向它的 .lnk，保留原入口交给 Shell。扫描不解析部署地址、不调用部署 handler、不安装应用；仅按类型索引，未声称验证任意 ClickOnce 内容。
- .lnk 优先 Shell 本地化显示名，原文件 stem、目标程序 stem 作为最多两个附加名称；归一化名、全拼、首字母仅在索引时生成，总键数最多 9。附加键每条最多 512 UTF-8 字节，附加字符串和键槽位的 owned 容量最多 2 KiB；整组超限跳过，不截断字符，不保留原别名或计数常驻字段。目标池仍限 512 项／128 KiB，超限目标在最终索引阶段按需重读。搜索不扫描、转换候选拼音或创建进程。
- 注册扫描每视图最多 20000 子键，值缓冲有界；16 MiB 预算计入 AppEntry／去重 identity 内联大小及 owned payload。Vec 富余槽位、HashSet 桶、分配器和读取缓冲另计，不能当作完整进程上限。
- 缓存文件名保持 apps-v1.bin，写 v3，读 v1／v2／v3；保存目标 tag、Path 与基础键数量，有界加载，不转换候选拼音。当前生成的 v3 能往返；外部非规范键组即便满足加载边界，也不承诺再次保存成功。
- --source 保持替代全部默认来源；未加入 PATH、游戏协议、watcher、周期轮询或运行时脚本。AppsFolder／AUMID 路径保留，尚未与 Flow 做完整包清单差分。

系统依据为微软 [Application Registration](https://learn.microsoft.com/en-us/windows/win32/shell/app-registration) 和 [Accessing an Alternate Registry View](https://learn.microsoft.com/en-us/windows/win32/winprog64/accessing-an-alternate-registry-view)。本机隔离实验中直接 Shell 打开完整 EXE 未附加注册 Path，按名称启动在高完整性、EnableLUA=0 环境失败；不能泛化所有 Windows 配置。helper 用受控程序证明精确目标和私有环境，没有完整模拟其他注册字段。

## 功能验证

最终 cargo fmt --check、cargo test --offline（91 单元＋7 集成）、cargo clippy --offline --all-targets -- -D warnings、cargo build --release --offline、git diff --check 通过。覆盖旧缓存、注册字符串／引号／展开／失效项、Unicode、环境边界、不同映射、来源故障回补、删除、别名排序及中文／全拼／首字母／中英混合。

native_probe.exe --discovery-sources 三轮默认、两轮自定义来源均正常退出，共 67 成功断言：受控 StartMenu 根入口、两类 HKCU 视图读取、共享视图去重、跨进程缓存、F5 修改／删除／恢复通过。注册入口启动受控无参数子程序，确认 Path 更新和父环境不变；原 .lnk 的 Unicode 参数与工作目录保持。自定义来源只含两个应用入口，中文／全拼／首字母／目标文件名命中同一原快捷方式；ClickOnce 索引、缓存、删除／恢复通过，缺失引用不触发部署。

实际本地化验证在自有忽略目录用 desktop.ini 资源把受控 .lnk 显示为“桌面”，独立 LoadStringW 一致。v3 保存该名称，本地化名、原文件名、EXE 名三类原生 Edit 查询命中原入口；未发送 Enter，正常退出。

helper 生命周期复验：73.885 ms 返回成功时受控 GUI 子程序已启动且仍存活，随后按测试设定退出；父 PATH 不变。单次功能样本不是 P50／P95 性能承诺，也未测 helper 与目标程序的并发总内存。

先前自定义来源在全部功能断言后退出触发 windows.storage.dll 10.0.19041.2788 +0x46668c / 0xC0000005。同样本仅改变分隔符：混合路径三轮异常、标准路径三轮正常；冻结来源扩展前 EXE 亦复现同一异常。文件系统 Shell 边界统一 UTF-16 分隔符后，混合／标准路径各三轮正常退出，原三默认／两自定义探针也完整通过。保存入口不变，不 canonicalize、不延迟退出、不跳过 COM 释放；通用字符串、AUMID、环境不改。无调用栈定位某个 Shell 内部函数，不能声称修复所有系统 DLL 问题；失败材料保留，不计为通过。

HKLM 没有实际注册 fixture；双 hive 实现已审查，冲突环境用私有源测试，不能声称实测所有系统优先级。Startup 排除用隔离目录测试，未创建真实登录自启动项。ClickOnce 成功激活未验证，没有安装应用、修改关联或打开个人安装应用。

## 证据与使用

可运行文件为 D:\workspace\PicoRun\target\release\picorun.exe。退出旧进程后运行工作区版本，F5 刷新；图标可在托盘开启，按本机 DPI 请求物理尺寸。

真实路径、清单、缓存和截图留在已忽略 runtime，不提交个人数据：

- runtime/probe-discovery-sources/：67 成功断言、计时、完整进程 CSV、缓存、截图。此前异常批次在 probe-discovery-sources-before-normalized-shell/。
- runtime/slash-driver/：原失败、冻结旧版事件、修复六轮和实际 PS1／C# 驱动；旧版超时回收没有记为成功。
