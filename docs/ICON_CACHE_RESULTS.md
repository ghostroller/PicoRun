活动 CPU 中位数 9.9375 → 8.53125 s，减少 1.40625 s（14.2%）。五轮依次为优化前 9.9375、10.40625、10.09375、9.796875、9.421875 s；优化后 8.75、8.53125、8.546875、8.390625、8.234375 s，五轮均减少。CPU 时间是所有应用线程使用的处理器时间之和，不是响应等待时间或持续 CPU 占用百分比。

新结果文字绘制中位数 5.9622 → 5.0657 ms，减少 15.0%；文字与图标全部就绪中位数 9.9159 → 8.1350 ms，减少 18.0%。P95 的下降较小，不能将中位数的收益用于所有尾延迟。绘制一次完整列表的成本没有得到改善；收益主要来自少做解析/提取，以及图标完成后避免重绘未改变的文字。同一查询和首次呼出也受 GDI、前台切换、调度和文件缓存影响，没有做统计显著性检验。

私有提交中位数 −0.08 MiB，工作集中位数 +0.13 MiB，属于小变化；不能宣称降低了常驻内存。优化后相对本轮无图标，私有提交仍多约 1.50 MiB、工作集多约 2.50 MiB，累计私有提交峰值最大值仍多约 9.96 MiB。针对最低内存目标，图标默认关闭的建议保持不变。

## 缓存实际做了什么

1. **单独保存解析结果**：入口路径映射到展开环境变量后的图标资源路径与索引，按需解析，最多 512 条；保守计算的缓存结构、路径和资源描述总计限制为 128 KiB，不全量加载应用图标。
2. **按资源共享图标**：相同原样资源路径与索引共用资源状态和 HICON，资源图标 LRU 上限继续为 48。保留负资源 ID；路径没有强制小写或文件系统规范化，避免额外扫描和错误合并。
3. **共享负结果和通用图标**：资源没有图标时保存负结果；整个工作线程最多复制一个系统通用图标。失败结果随缓存失效重新尝试。
4. **复用已绘制的文字**：图标完成后只标记图标列为更新区域，跳过与更新区域不相交的结果文字和页脚绘制。没有新增整屏位图缓冲。Win32 的 BeginPaint 会限制 DC 到更新区域。[BeginPaint](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-beginpaint)、[InvalidateRect](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-invalidaterect)

所有资源解析、图标提取仍在一个懒创建的 STA 线程；最新请求替换过期请求、匹配代次后更新显示、容量为 1 的完成队列、空闲条件变量阻塞。没有增加依赖、后台周期轮询、应用发现扫描或启动进程。

元数据账目包含容器已分配槽位、路径 capacity 和 Rc 控制块；共享描述在每个引用处重复计入，属于保守估计。128 KiB 不包含两个复用的 UTF-16 工作缓冲（另计 128 KiB）、图标像素、线程栈、查询/显示快照和系统组件。48 个资源图标之外，通用图标额外共享一个；当前/待消费快照可短暂持有已淘汰的图标引用，不承诺整个进程严格只有 49 个 HICON。

F5/托盘刷新和 DPI 变化会使优化缓存失效；下一次请求重新解析和提取。未做文件变更轮询、跨进程持久化像素缓存或磁盘缓存；进程内缓存首次加载仍可能出现资源提取峰值。

| 前 200 次名称查询的资源提取次数 | 每轮 224 | 每轮 166，减少 25.9% |
| 压力负载结束时解析次数中位数 | 877 | 220，减少 74.9% |
| 压力负载结束时资源提取次数中位数 | 877 | 844 |

名称查询可以返回多个匹配入口，所以前 200 个名称涉及 220 个解析结果。每次等待完成的 200 查询阶段，提取次数可以直接比较；1000 次快速轮换阶段会合并过期请求，优化后更多请求能够完成处理，不能把累计计数当作固定 1000 次独立访问。相同结果集合的重复查询被 Session 跳过，不进入上述后台命中率。

500 个受控快捷方式，三种配置各 3 个进程，操作流程与真实样本一致。前 200 个受查询入口只有两组资源：同一个没有自有图标的测试 exe，以及一个 `%SystemRoot%\System32\shell32.dll,-154` 自定义资源。因此该样本特别适合验证共享和负缓存，收益不能推广到 500 个各不相同的真实图标。

## 环境、口径与纯搜索

环境仍为 i7-11700K（8 核/16 线程）、32 GiB、Windows 11 Enterprise 25H2 build 26200 x64；Rust 1.95.0 MSVC，release opt-level=3、fat LTO、codegen-units=1、panic=abort、strip、静态 CRT、离线构建。MiB = 1,048,576 字节。

每进程隐藏启动后等待 100 ms 采样，再显示文字、等图标、等待 100 ms；列表绘制各预热 20 次、外部/内部各计时 200 次；内部计时也通过本线程 SendMessage(WM_PAINT) 进入标准窗口绘制路径。随后依次完成 200 个名称查询、预热 20 次同一查询并计时 120 次、1000 次快速轮换，等最后一代图标完成，再隐藏等待 500 ms 和测 2 秒空闲。配置顺序循环 off/before/after、before/after/off、after/off/before。

CPU 活动时间从隐藏采样到连续查询结束；私有提交、工作集和系统维护的累计峰值取整个被测进程，包括其系统组件，排除驱动、Explorer 和其他进程，不是整个系统增量。峰值从进程创建累计，包含发现、显示、绘制与取图。没有清空工作集或系统文件缓存；每次是新的进程内图标缓存，应用缓存后续复用，每次仍发现入口，不称为磁盘冷启动。窗口探针含同步 Edit、消息 IPC、搜索和绘制，不是物理按键到屏幕时间。

P50/P95 使用最近秩。内存 n=5/n=3 时 P95 就是最大值；重复计时先计算每进程的 P50/P95 再取进程间中位数；启动/首次呼出每进程仅一条，直接取独立进程间 P50/P95。少量进程不能预测最低配机器的尾延迟。实验窗口仍使用独立类/单实例名，抑制失焦隐藏和物理快捷键，使用自身英文布局；本次没有重做真实中文 IME、热键和所有窗口行为的正式验收。

搜索、拼音和排序代码未改变。最终 GUI 实验结束后，优化原型的 search_bench 独立运行 3 次，固定一个 CPU 核；每规模构建并测一次首次搜索，预热 20×12 查询，再测 100×12=1200 次。下表取三次中位数，不能把波动解释为图标优化导致的搜索算法收益。

## 重建与证据

正式 exe 仍为 638,464 字节，SHA256 `55056038F3D204791C604C4B18572775961DC446EB8504C42FA8FE07FB9AAF16`。最终被测实验 exe 为 710,144 字节，SHA256 `17B559CD082D9B877E4D4A0715BAB8F46E1E400D1808DE099A706FCA3D43F932`；优化补丁 SHA256 `B4C61F04F46ACB89C916C47A1747BB5EE16C85496C97871124E1971FC7EF31C3`。

`tools/build_icon_experiment.ps1 -Optimized` 从提交 `1a0080f` 导出基线，依次应用原图标实验补丁和 `tools/icon_cache_optimization.patch`，在隔离目录执行 fmt、19 项测试、clippy 与 release 构建。需要 PowerShell 7、Rust MSVC 和 Windows SDK；拒绝覆盖已有目录。以下为复现命令，测量输出名可以另选，保留已测数据。

已在新目录 `runtime/icon-eval/optimized-rebuilt-verified` 实际重建，上述检查全部通过；全部 `src/` 文件逐一 SHA256 与被测原型一致。重建 exe SHA256 为 `52C9954C23358E010898016ACB102EF613C223085FE7F74BBC3062EEF13CFCC0`，与被测 exe 不同，不声称二进制逐字节可复现。

```powershell
pwsh -File tools/build_icon_experiment.ps1 -Optimized
pwsh -File tools/prepare_icon_fixture.ps1 -Prototype runtime/icon-eval/optimized-rebuilt
pwsh -File tools/measure_icons.ps1 -Prototype runtime/icon-eval/optimized-rebuilt -CompareCache -Real -Runs 5 -Output cache-real-repro
```

最终原始数据在忽略目录 `runtime/icon-eval/cache-real-verified`、`cache-synthetic-verified`、`cache-validation-final`；汇总为 cache-comparison.json，纯搜索为 search-cache-1..3.txt。先前的 cache-real/cache-synthetic 用于定位单独缓存的收益，cache-real-final/cache-synthetic-final 用于试验局部重绘，不混入最终数字；原始数据均保留。个人索引/路径只在忽略目录，报告和截图没有导出个人应用清单。

Windows 10、x86、极低配 CPU、慢/网络资源、低内存换页仍未实测；当前优化不能消除首次资源提取成本，也没有提供跨进程持久缓存。正式图标功能尚未合并，默认关闭建议保持。
